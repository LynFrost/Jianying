# Key Manager replacement V0.06 升级方案

## 1. 升级范围

本版本基于 `key-manager-replacement-v0.05.ahk` 规划，目标文件为：

`key-manager-replacement-v0.06.ahk`

V0.05 文件保留，不覆盖、不直接修改。

本次只调整小键盘减号、加号对应的滚轮功能。

## 2. 映射要求

| 快捷键 | 功能 |
|---|---|
| 左 Ctrl + 小键盘 - | 连续发送 8 次鼠标滚轮向上，保持现有功能 |
| 左 Ctrl + 小键盘 + | 连续发送 8 次鼠标滚轮向下，保持现有功能 |
| Shift + 小键盘 - | 连续发送 18 次鼠标滚轮向上 |
| Shift + 小键盘 + | 连续发送 18 次鼠标滚轮向下 |

其中 `Shift` 使用通用 Shift 修饰键，左 Shift 和右 Shift 均可触发。

主键盘区域的 `-`、`=`、`+` 不增加映射。

## 3. 深层原因

V0.05 的 `StableWheel()` 在执行前后调用 `ReleaseModifiers()`，会强制释放 Ctrl、Shift、Alt 和 Win 等修饰键。

对于原有的 `Ctrl + 小键盘 -/+`，这种处理可以避免 Ctrl 被带入滚轮事件，但它也意味着脚本会主动改变当前修饰键状态。

新增 `Shift + 小键盘 -/+` 后，如果继续无条件释放所有修饰键，执行过程可能出现以下状态变化：

1. 用户实际仍按住 Shift；
2. 脚本向系统发送 Shift 松开事件；
3. 脚本发送滚轮事件；
4. 用户松开实体 Shift 前，系统内部的 Shift 状态可能已经与实体按键不同步。

这可能影响后续大写输入、Shift 选择文本、Shift 点击和 Shift 加方向键等操作。

## 4. 实现方案

### 4.1 分离滚轮次数

保留原有滚轮次数，并增加 Shift 滚轮次数：

```ahk
WheelSteps := 8
ShiftWheelSteps := 18
```

原有 Ctrl 映射继续使用 `WheelSteps`，新增 Shift 映射使用 `ShiftWheelSteps`。

### 4.2 新增快捷键

规划新增：

```ahk
+NumpadSub::StableWheel("Up", ShiftWheelSteps, "NumpadSub")
+NumpadAdd::StableWheel("Down", ShiftWheelSteps, "NumpadAdd")
```

原有映射保持：

```ahk
<^NumpadSub::StableWheel("Up", WheelSteps, "NumpadSub")
<^NumpadAdd::StableWheel("Down", WheelSteps, "NumpadAdd")
```

### 4.3 保护修饰键状态

滚轮函数改为接收滚轮次数，并在执行过程中：

1. 记录左、右 Shift、Ctrl、Alt、Win 的实际按键状态；
2. 临时释放会影响滚轮解释的修饰键；
3. 发送指定次数的滚轮事件；
4. 根据滚轮发送完成时的实际物理状态恢复仍被按住的修饰键；
5. 等待对应的小键盘按键松开。

这样可以避免因为发送滚轮而永久清除用户正在按住的 Shift 或其他修饰键。

## 5. Ctrl + Shift 组合键

本版本不专门为 `Ctrl + Shift + 小键盘 -/+` 增加第三套功能。

设计意图如下：

- 单独使用 `Ctrl + 小键盘 -/+` 时执行 8 次滚轮；
- 单独使用 `Shift + 小键盘 -/+` 时执行 18 次滚轮；
- 同时按住 Ctrl 和 Shift 时，不新增专用行为，避免两套映射互相竞争或误触发。

## 6. 预期副作用与限制

### 6.1 Shift + 小键盘 -/+ 将覆盖原功能

启用脚本后，Shift 加小键盘减号或加号不再交给当前软件处理，而是执行滚轮操作。这是本次需求明确要求的行为。

### 6.2 滚动距离与视觉效果不完全固定

脚本发送的是 18 个标准滚轮事件。不同软件可能使用不同的滚动行数、页面滚动逻辑或平滑滚动策略，因此实际看到的滚动距离不一定完全相同。

### 6.3 快速按键时的状态恢复

如果用户在滚轮序列执行期间快速按下或松开 Shift，脚本需要根据结束时的物理状态恢复修饰键。极短时间内的按键变化仍可能受到 Windows 输入处理时序影响。

### 6.4 其他程序的特殊输入处理

管理员权限窗口、远程桌面、虚拟机、游戏或使用独立输入系统的软件，可能不会完全按照普通 Windows 程序处理模拟滚轮事件。这属于输入接收端差异。

## 7. 版本文件处理

确认执行后按以下顺序处理：

1. 复制 `key-manager-replacement-v0.05.ahk` 为 `key-manager-replacement-v0.06.ahk`；
2. 只修改 V0.06 文件；
3. 保留 V0.05 及更早版本；
4. 使用本机 AutoHotkey v2 检查脚本语法；
5. 不让脚本因检查过程而长期驻留运行。

当前文档阶段不创建 V0.06 脚本。
