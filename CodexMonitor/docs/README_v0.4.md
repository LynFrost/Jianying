# CodexMonitor v0.4 — B1 多屏、缩小窗口、被遮挡时的后台监控

## 文件和启动

- **主程序：`CodexMonitor_v0.4.ahk`**，直接双击运行（AutoHotkey v2）。
- **本说明：`README_v0.4.md`**；日志自动保存为 `CodexMonitor_v0.4.log`。
- **依赖：`vendor/UIA-v2/UIA.ahk`**，随程序附带；采用 Descolada/UIA-v2 开源库，授权见 `vendor/UIA-v2/LICENSE`，固定来源版本见 `SOURCE.txt`。
- v0.1、v0.2、v0.3 文件全部保留，不覆盖；**启动 v0.4 前必须先在托盘退出任何仍在运行的旧版**，避免快捷键和点击冲突。

## B1 能力及边界

| 环境 | 预期行为 |
| --- | --- |
| ChatGPT 前台窗口 | 优先 UI Automation；无法读到按钮时回退到 v0.3 的视觉识别及前台点击 |
| ChatGPT 在另一屏、未最大化 | 通过 HWND 和窗口相对位置识别，不依赖固定分辨率或最大化 |
| VS Code / 浏览器覆盖 ChatGPT | **只允许 UIA InvokePattern 后台调用**，不得移动鼠标或激活 ChatGPT |
| UIA 读不到可区分的停止/继续状态或无法 Invoke | 显示“不可可靠操作”，**继续监控但不自动点击** |
| ChatGPT 最小化（B2，不在本版范围） | 视为暂不可用；仍保持监控，恢复窗口后自动重新检测 |
| 程序关闭/窗口找不到/多个候选窗口无法确定 | 显示状态和不重复的通知，等待下一轮检查，不退出程序 |
| 窗口换屏/拖动/缩放 | 下次轮询重新按窗口句柄、相对位置定位 |
 
**重要：B1 后台 Invoke 的实际兼容性尚需在你正在使用的 ChatGPT 桌面版本中验证。** 目标应用可能没有可调用的 UIA 按钮，或按钮的可访问名称不符合当前识别规则。在这种情况下，本程序安全地保持监控，不强行抢焦点。

## 操作快捷键

- **Ctrl + Shift + F12**：开始/停止监控。即使启动时找不到 ChatGPT 窗口也保持监控，最多每 10 秒再试。
- **Ctrl + Shift + F11**：自动模式 ↔ **测试模式（绝不点击）**。首次建议切换成测试模式。
- **Ctrl + Shift + F10**：**只读 UI Automation 诊断**，将目标窗口下部按钮的可访问名称、位置、是否支持 Invoke 写入日志，不点击鼠标。日志只包含按钮标签及几何信息，不抓取对话内容。
- 右上角悬浮文字会显示：监控中 / 目标不可用 / UIA 或视觉识别 / 已锁定等。
- 监控正常周期 10 秒；点击后最多 15 秒以 250ms 观察恢复。窗口缺失或不可操作不清除点击锁定，不超时重试。

## 如何验证真正后台可用性

1. 退出所有旧版；双击 `CodexMonitor_v0.4.ahk`。
2. 先 **Ctrl+Shift+F11** 进入测试模式，再按 **Ctrl+Shift+F12** 启动。
3. 将 ChatGPT 缩小放到任意显示器，窗口保持非最小化。切到 VS Code 或浏览器让其被遮挡。
4. 按 **Ctrl+Shift+F10**，打开 `CodexMonitor_v0.4.log` 查看 `UIA底部按钮`、`kind`、`invoke`。如果没有找到，可在 ChatGPT 继续/停止两种状态分别诊断。
5. 若日志存在 `检测1=triangle; method=uia` 和 `检测1=square; method=uia`，说明状态读取路径有希望；**这还不代表 Invoke 点击已经成功**。
6. 需要实际点击测试时，切回自动模式，保持其他软件为前台。观察日志的 `UIA后台调用一次`、`前台之前/之后`，以及 ChatGPT 是否真正恢复。必须验证没有切走焦点，且下一次只有观察到稳定方形才解锁。
7. 如果日志一直显示 `后台按钮没有可靠UIA状态`，说明当前 ChatGPT 版本/布局未暴露明确控件。可以提供这份日志再针对性调整定位或名称匹配，**不应靠猜测强制点击**。

## 保护机制（继承方案 A）

- 三次确认三角形，位置和识别方式一致，才允许单次操作。
- 优先 UI Automation InvokePattern；普通鼠标 `Click` **只在同一个 ChatGPT 窗口为前台时使用**。
- 点击之前锁定，不会在 10 秒后重复点击；只有稳定方形至少三次、跨越至少 500ms 才能解锁。
- 若因切换软件、窗口消失、最小化、识别异常而暂停，**仍然锁定**，不把无法识别误判成成功恢复。
- 提示使用托盘通知和悬浮文字，不用反复弹出的对话框中断你的工作。
- 已经在脚本中避免主动 `WinActivate`；但第三方 UIA 控件收到 `Invoke` 后是否改变焦点，取决于 ChatGPT 的实现。日志会记录调用前后前台窗口，以便验证。

## 非点击自动化测试

在文件夹中可使用 AutoHotkey v2 执行：
- `CodexMonitor_v0.4.ahk --self-test`：合成方形/三角形、锁定机制、UIA 标签分类。
- `CodexMonitor_v0.4.ahk --uia-test`：只读验证 Windows UI Automation COM 根接口。
- `CodexMonitor_v0.4.ahk --capture-test`：验证 GDI 截图缓存。
- `CodexMonitor_v0.4.ahk --screen-test`：检查 ChatGPT 窗口一次（支持窗口在后台），不点击。
 
以上各项均不会自动点击，也不会启动持续监控。

## 已知限制

B1 不包含最小化窗口后台控制。UIA accessibility 属性不等同于按钮的像素形状，因此遇到未命名按钮、按钮不可调用、混淆候选、多个桌面窗口、UI 更新等情况可能只检测到 `unknown`。支持遮挡的关键在于目标应用是否暴露足够的 UIA 属性和 InvokePattern；这不是 AutoHotkey 可以强制保证的功能。Windows 定时器、UIA 查询和应用 UI 更新均不属于硬实时系统。
